## 二、本周踩坑问题汇总与解决方案

1. Python 安装时未勾选添加环境变量，终止执行 `python` 命令提示找不到指令；解决方案：重新运行安装包选择 Modify，勾选 `Add
   Python to PATH`
2. 同一代码块混合使用空格和 Tab 缩进，触发 `IndentationError` 缩进错误；解决方案：PyCharm 中设置统一使用 4 个空格缩进，按
   Tab 自动转换为空格，全程避免混合使用
3. 字典直接使用 `[]` 取值，键不存在时触发 `KeyError` 导致程序中断；解决方案：优先使用 `dict.get(key, 默认值)`
   方法取值，不存在时返回默认值，避免程序意外崩溃
4. `w` 模式打开已有文件，原有内容被全部清空导致数据丢失；解决方案：写入前确定文件模式，追加内容使用 `a` 模式，修改原有内容先读取到内存再写入
5. `input` 接收的数值直接参与运算，触发 `TypeError` 类型错误；解决方案：`input` 返回值永远为字符串类型，数值运算前必须用
   `int()` / `float()` 显式转换类型
6. JSON 序列化中文显示为 Unicode 编码，可读性差；解决方案：`json.dumps()` / `json.dump()` 时添加 `ensure_ascii=False`
   参数，保留原始中文
7. 手动字符串拼接路径，跨 Windows / Linux 平台出现路径分隔符不兼容；解决方案：统一使用 `os.path.join()` 拼接路径，自动适配当前系统的分隔符
8. 函数内修改全局变量不生效，被识别为局部变量；解决方案：函数内修改全局变量前，使用 `global 变量名` 显式声明
9. 元组只有一个元素时未加逗号，被识别为单个元素而非元组；解决方案：单个元素的元组必须再元素后添加逗号，如 `(10,)`
10. 空集合直接用 `{}` 创建，实际生成空字典；解决方案：空集合必须用 `set()` 创建，`{}` 为创建空字典的语法
