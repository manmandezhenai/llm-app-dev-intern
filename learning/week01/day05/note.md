# Week01-Day05：模块、包与异常处理

## 【核心知识点】

### 1. 模块与导入机制

- 模块定义：单个 `.py` 文件就是一个模块，可封装变量、函数、类，实现代码复用与拆分
- 四种导入方式：
    - `import 模块名`：导入整个模块，使用时需加模块前缀
    - `from 模块名 import 成员名`：导入模块中指定成员，直接使用无需前缀
    - `from 模块名 import *`：导入模块所有公开成员，不推荐在工程代码中使用
    - `import 模块名 as 别名`：给模块 / 成员起别名，解决命名冲突
- 导入规范：导入语句统一放在文件顶部，按「标准库 → 第三方库 → 自定义模块」顺序排序，类别间空一行
- 入口判断：`if __name__ == "__main__":`，直接运行脚本时执行，被导入时不执行，用于模块测试

### 2. 自定义包

- 包定义：包含 `__init__.py` 文件的目录，用于组织多个关联模块，解决命名冲突
- `__init__.py` 的作用：标识目录为 Python 包；可定义 `__all__` 变量控制 `import *` 导出范围；可预先导入内部成员简化外部调用
- 包导入方式：
    - `from 包名 import 模块名`：导入包内指定模块
    - `from 包名.模块名 import 成员名`：直接导入包内模块的成员
- 相对导入：`.` 代表当前目录，`..` 代表上级目录，仅能在包内部模块间使用，不能直接运行脚本

### 3. 异常处理完整结构

- 异常概念：程序运行时的错误事件，不捕获处理会导致程序直接终止
- 完整语法结构：

```python
try:
    可能抛出异常的业务代码
except 异常类型1:
    捕获异常类型1并处理
except 异常类型2:
    捕获异常类型2并处理
else:
    无异常时执行
finally:
    无论是否异常都执行，用于资源释放
```

- 捕获规则：多个 `except` 按从上到下顺序匹配，子类异常必须放在父类异常之前
- 最佳实践：优先捕获具体异常，避免裸 `except`；`finally` 只做资源清理，不写业务逻辑

### 4. 异常抛出与自定义异常

- 主动抛出：使用 `raise 异常类("错误描述")`，用于参数校验、业务规则不满足等场景
- 常见内置异常：

| 异常类型                | 触发场景                    |
|---------------------|-------------------------|
| `TypeError`         | 类型不匹配，如字符串与数字相加         |
| `ValueError`        | 类型正确但值非法，如 `int("abc")` |
| `IndexError`        | 列表 / 字符串索引超出范围          |
| `KeyError`          | 字典中不存在对应的键              |
| `FileNotFoundError` | 读取的文件路径不存在              |

- 自定义异常：继承 `Exception` 类，通常只需要定义构造函数，用于区分业务场景的专属错误
- 工程价值：统一错误处理逻辑，快速定位问题类型，提升代码健壮性

## 【今日易错点】

1. 自定义包目录缺少 `__init__.py` 文件，会被识别为普通目录而非 Python 包
2. `except` 捕获顺序错误，父类异常放在子类前面会导致子类异常永远无法匹配
3. `finally` 中编写 `return` 语句，会覆盖 `try` 和 `except` 中的返回值，导致业务逻辑错误
4. 主动抛出异常使用 `print` 只会输出文字，不会触发异常机制，必须使用 `raise` 关键字
5. 裸 `except` 会捕获所有异常包括系统退出类异常，排查问题困难，工程中不推荐使用
6. 相对导入只能在包内部模块中使用，直接运行包含相对导入的脚本会报错
7. 导入的模块名与当前文件的变量名重名，会覆盖模块对象导致调用失败
8. 模块不在 Python 搜索路径中时，直接导入会触发 `ModuleNotFoundError`
